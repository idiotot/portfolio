# 운영 사이트 개선 및 검증

## 사전 상태

개선 기준은 main `3f8ee67167db559b0576f180e495bff001903a3c`이다. 로컬·원격 main이 일치하고 미커밋·미추적 파일은 없었다. 해당 SHA의 Pages 실행 42367850584는 성공하였다. Hugo Extended 0.167.0, Bear Blog와 수업 제공 스크립트 3.1을 유지한다. 초기 이력은 전체 18개에서 원본 ZIP 단순 등록 1개를 제외한 유효 17개이다.

수정은 `site/`의 사용자 오버라이드와 운영 검증 코드에서 수행한다. 원본 테마·라이선스·`prepare_github_pages.py`·`.github/pages_build.py`는 보존한다. NAVI Study 앱과 DB 장애 복구 테스트는 이번 사이트 검증 대상에서 제외한다.

## 코드 구문 강조

Hugo의 인라인 색상 대신 Chroma 클래스 출력을 사용하여 실제 사용된 토큰의 색상을 CSS에서 정의하였다. 생성 HTML의 인라인 토큰 색상이 CSS를 덮어쓰는 문제를 방지하였다. 별도 라이브러리는 추가하지 않았다.

## 내비게이션 현재 위치

메뉴 URL과 정확히 일치하는 페이지에만 `aria-current="page"`를 적용한다. 하위 페이지는 슬래시로 구분한 경로 접두사를 비교하고 `is-section` 클래스로 상위 구간을 표시한다. 외부 링크와 `/projects/lms-extra/`처럼 이름만 유사한 경로는 현재 구간으로 처리하지 않는다.

`/tmp` 복사본의 홈·소개·프로젝트·구현 노트 HTML에서 정확한 페이지와 상위 구간 표시를 대조하였다. 별도의 임시 `/projects/lms-extra/` 페이지도 빌드하여 잘못된 접두사 일치를 방지함을 확인하였다. 임시 페이지는 운영 소스에 추가하지 않았다.

## 긴 문서의 목차

프로젝트·구현 노트에만 Hugo의 `TableOfContents`를 적용하였다. h2·h3의 기존 계층과 사용자 지정 ID를 유지하며 별도 JavaScript를 사용하지 않는다. 목차와 헤더 메뉴의 스타일을 분리하여 수평 메뉴 스타일이 목차에 전파되지 않도록 하였다.

기준 빌드에 존재했던 모든 ID가 유지되었으며, 두 문서의 목차가 참조하는 ID가 모두 존재함을 확인하였다. 홈과 소개에는 목차를 추가하지 않았다.

## 홈 미리보기 이미지 회귀와 기록 정정

`1394870`은 이미지 치수를 출력하는 중첩 shortcode를 도입하였다. 그러나 바깥 `project-preview`의 `markdownify`가 내부 shortcode의 HTML을 다시 처리하면서 제거하였다. Hugo 자체는 종료 코드 0이었으나 경고가 발생하였고, 생성 HTML의 이미지 존재 검사도 실패하였다.

해당 커밋의 “생성 HTML의 치수·경로·alt를 확인하였다”는 성공 문구는 실제 결과와 일치하지 않았으며 무효이다. 명령 실행 결과를 확인하기 전에 뒤이은 커밋 명령까지 실행한 절차상의 오류가 원인이었다. 기존 이력은 재작성하지 않고 이 후속 기록으로 정정한다. 해당 회귀는 로컬에서 발견되었으며 원격 main에는 배포하지 않았다.

복구에서는 새 이미지 shortcode를 제거하고 기존 Markdown 이미지와 링크를 복원하였다. 홈의 실제 이미지 1360×860에 대응하는 CSS `aspect-ratio: 1360 / 860`만 프로젝트 카드 이미지에 적용하였다. 원본 PNG·alt·목적지와 기존 템플릿 구조를 유지하였다. 전역 HTML 허용과 외부 의존성은 추가하지 않았다.

복구 후 정적 검사와 실제 브라우저 검사를 별도로 수행한 뒤 최종 판정을 기록한다. CLS를 실측하지 않았으므로 개선 수치를 제시하지 않는다.

## 복구 후 최종 로컬 판정

정적 검사는 Hugo Extended 0.167.0 및 수업 제공 원본 스크립트로 `/tmp` 복사본을 빌드한 결과를 대상으로 수행하였다. HTML 6개, 내부 참조 94개, 앵커 참조 46개, CSS SRI 6개가 오류 없이 확인되었다. 기준 빌드의 모든 기존 ID를 보존하였고 홈 이미지 1개와 프로젝트 이미지 3개를 확인하였다.

실제 브라우저에서는 홈·소개·프로젝트·구현 노트를 1440·768·390px에서 검사하였다. 총 12개 조합에서 본문·목차·메뉴의 넘침이 없었다. 네 페이지의 1440→390→1440 연속 변경과 메뉴 이동·뒤로 가기·새로고침 후 표시도 유지되었다.

홈 이미지는 세 화면 폭에서 1360×860 원본으로 로드되었으며 CSS 종횡비와 대체 텍스트·프로젝트 링크가 유지되었다. 프로젝트 이미지 3개도 로드되었고 각 원본 링크를 실제로 열어 확인하였다. 두 문서의 목차에서 Enter 이동 시 기존 검증 섹션에 도착하였으며, 본문 건너뛰기와 코드의 가로 스크롤도 키보드로 동작하였다.

브라우저에서 읽은 실제 토큰·배경 색상으로 다시 계산한 대비는 숫자 6.11:1, 주석 5.24:1, 타입명 7.13:1, 문자열 6.15:1, 키워드 5.48:1이다. 해당 결과는 위 CSS 계산과 일치한다.

따라서 이미지 회귀의 최종 로컬 판정은 **복구 확인**이며, `1394870`의 부정확한 성공 기록은 본 정적·브라우저 검사 결과로 대체한다. 실제 200% 확대는 브라우저 도구의 배율 변경을 검증하지 못하여 **UNVERIFIED**이다. 작은 화면 검사를 확대 검사로 대체하지 않는다.

검증 스크립트의 저장소 내 일반화와 CI 통합은 이번 배포에서 보류하였다. 기존 배포 워크플로와 수업 제공 스크립트는 변경하지 않았다. NAVI Study의 DB 장애 복구 테스트는 재실행하지 않았다.
