# 운영 사이트 개선 및 검증

## 사전 상태

개선 기준은 main `3f8ee67167db559b0576f180e495bff001903a3c`이다. 로컬·원격 main이 일치하고 미커밋·미추적 파일은 없었다. 해당 SHA의 Pages 실행 42367850584는 성공하였다. Hugo Extended 0.167.0, Bear Blog와 수업 제공 스크립트 3.1을 유지한다. 초기 이력은 전체 18개에서 원본 ZIP 단순 등록 1개를 제외한 유효 17개이다.

수정은 `site/`의 사용자 오버라이드와 운영 검증 코드에서 수행한다. 원본 테마·라이선스·`prepare_github_pages.py`·`.github/pages_build.py`는 보존한다. NAVI Study 앱과 DB 장애 복구 테스트는 이번 사이트 검증 대상에서 제외한다.

## 코드 구문 강조

Hugo의 인라인 색상 대신 Chroma 클래스 출력을 사용하여 실제 사용된 토큰의 색상을 CSS에서 정의하였다. 생성 HTML의 인라인 토큰 색상이 CSS를 덮어쓰는 문제를 방지하였다. 별도 라이브러리는 추가하지 않았다.

## 내비게이션 현재 위치

메뉴 URL과 정확히 일치하는 페이지에만 `aria-current="page"`를 적용한다. 하위 페이지는 슬래시로 구분한 경로 접두사를 비교하고 `is-section` 클래스로 상위 구간을 표시한다. 외부 링크와 `/projects/lms-extra/`처럼 이름만 유사한 경로는 현재 구간으로 처리하지 않는다.

`/tmp` 복사본의 홈·소개·프로젝트·구현 노트 HTML에서 정확한 페이지와 상위 구간 표시를 대조하였다. 별도의 임시 `/projects/lms-extra/` 페이지도 빌드하여 잘못된 접두사 일치를 방지함을 확인하였다. 임시 페이지는 운영 소스에 추가하지 않았다.

## 긴 문서의 목차

프로젝트·구현 노트에만 Hugo의 `TableOfContents`를 적용하였다. h2·h3의 기존 계층과 사용자 지정 ID를 유지하며 별도 JavaScript를 사용하지 않는다. 목차와 헤더 메뉴의 스타일을 분리하여 수평 메뉴 스타일이 목차에 전파되지 않도록 하였다.

기준 빌드에 존재했던 모든 ID가 유지되었으며, 두 문서의 목차가 참조하는 ID가 모두 존재함을 확인하였다. 홈과 소개에는 목차를 추가하지 않았다.

## 홈 미리보기 이미지

배포 기준 HTML에서 홈 이미지에 width·height가 없음을 확인하였다. 홈의 해당 이미지에만 원본 파일을 읽는 `imageConfig` 기반 shortcode를 적용하여 1360×860 치수를 출력하였다. 링크·대체 텍스트와 원본 PNG는 유지하였다. 기존 프로젝트 이미지 3장은 이미 치수를 보유하므로 변경하지 않았다.

생성 HTML의 치수·경로·alt를 확인하였다. 치수는 로딩 전 공간을 확보하기 위한 정보이며, CLS 실측값은 별도로 측정하지 않았으므로 수치를 제시하지 않는다.
