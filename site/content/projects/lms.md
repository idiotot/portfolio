2026년 11월 · 개발 중 · 개인 프로젝트

## 프로젝트 개요

NAVI Study는 과목별 자료 탐색과 과제 마감 근거 확인을 목적으로 개발 중인 데스크톱 프로그램이다. Rust workspace 내에 저장 계층, 카탈로그 변환기 및 Iced GUI를 분리하여 구현하였다.

**현재 GUI는 가상 데이터 기반 프로토타입이다.** SQLite 저장 모듈은 별도로 구현되어 있으나, GUI의 실제 자료 조회 및 저장 기능과는 아직 연계하지 않았다.

### 작업 범위 {#내가-맡은-작업}

개인 프로젝트로 자료 모델, 저장·변환 모듈 및 GUI의 검색·필터·상태 처리를 구현하였다. 설계, 코드 작성과 검증 과정에는 AI 도구의 지원을 활용하였다.

## 개발 배경 {#해결하고-싶은-문제}

LMS의 강의 자료·공지·과제 정보는 서로 다른 화면에 제시되므로 자료 탐색과 마감 확인 과정에서 반복적인 조회가 필요하다. 또한 본문에 기재된 마감일과 등록된 마감 정보가 일치하지 않는 경우에는 근거를 대조해야 한다.

이에 과목별 자료를 정리하고 마감 정보의 출처를 함께 확인할 수 있는 로컬 관리 도구를 개발 대상으로 설정하였다.

## 기술 선정 및 시스템 구성 {#구현-과정과-선택}

| 기술 | 적용 범위 |
| --- | --- |
| Rust | 자료 검증·변환·저장 모듈 및 GUI 상태 처리 |
| SQLite · rusqlite | 자료 레코드, 관측 시각 및 범위별 처리 상태 저장 |
| Iced 0.14 | 과목·자료 목록, 검색·필터, 일정 및 근거 화면 |

### Rust 선정 근거

Rust를 구현 언어로 선정하였다. 주요 선정 기준은 높은 런타임 성능, 컴파일 단계의 정적 검증, 메모리 안전성 및 향후 기능 확장 가능성이었다.

Rust는 가비지 컬렉터에 의존하지 않고 소유권과 빌림 체계를 통해 메모리 접근과 자원 수명에 관한 제약을 컴파일 단계에서 검증한다. 안전한 Rust 코드에서 데이터 경쟁과 다수의 메모리 안전성 관련 오류를 예방할 수 있다는 점을 고려하였다.

Cargo의 패키지 관리 및 workspace 구성은 모듈화에 유리하다. 현재 프로젝트도 저장·변환·GUI를 세 crate로 분리하였다. 소유권과 타입 시스템에 대한 학습 비용이 존재하나, 기술적 요구사항과 장기적인 확장 가능성을 종합적으로 고려하여 채택하였다.

위 내용은 언어 선정 근거이며, NAVI Study의 런타임 성능을 실측한 결과는 아니다. 프로그램의 성능 측정은 후속 검증 과제로 남아 있다.

### Iced 및 SQLite 적용 구조

저장·변환·GUI를 같은 Rust workspace에 배치하고, Iced GUI가 변환기의 결과를 사용하도록 구성하였다. GUI는 tiny-skia 렌더러를 사용하며 Chromium 또는 Electron을 포함하지 않는다. SQLite는 별도 서버를 운영하지 않고 로컬 파일에 데이터를 저장하는 구조로 적용하였다.

저장 모듈은 `records`에 자료 종류·원본 식별자·제목·JSON payload를 기록하고, `watermarks`에 과목 및 자료 종류별 관측 시각을 기록한다. 두 정보는 동일한 트랜잭션 내에서 갱신된다.

### 읽음·보관·검토 표시

선택한 자료의 읽음·보관 상태와 마감 검토 여부를 변경할 수 있다. 해당 상태는 GUI 메모리 내에서만 유지되며, 초기화 또는 프로그램 종료 후에는 보존되지 않는다.

## 주요 구현 과제 및 처리 방법 {#문제-해결}

### 중복 자료 처리

과목 ID, 자료 종류 및 원본 식별자가 동일한 문서를 하나의 그룹으로 구성한다. 그룹 내에서는 최신 `fetched_at`의 문서를 선택하며, 관측 시각이 동일한 경우 경로와 제목 순서로 결과를 결정한다. 게시판 자료는 게시판 ID와 글 ID를 함께 사용하여 서로 다른 글이 병합되지 않도록 하였다.

### 마감 근거의 불일치 판정

완전한 날짜·시각은 시차를 반영한 동일 시점인지 비교한다. `Z` 표기와 시차 표기가 달라도 동일한 시점이면 중복 후보로 처리한다. 지원 범위 내에서 서로 다른 완전한 시각이 남는 경우에는 `Conflict`로 분류한다.

본문에 월·일만 기재되어 있고 공식 시각과 일치하지 않는 경우에는 연도나 시간을 임의로 보충하지 않는다. 이 경우 `Unknown` 상태와 추가 확인이 필요한 근거를 반환한다. 임의의 자연어 날짜 전체를 해석하는 방식은 구현 범위에 포함하지 않았다.

### 검토 상태와 마감 판정의 분리

UI의 검토 표시와 마감 판정 데이터를 분리하였다. `Acknowledge`는 검토 표시 집합만 변경하며, `Unknown` 또는 `Conflict`를 `Confirmed`로 전환하지 않는다. 해당 관계는 자동 테스트로 검증하였다.

## 테스트 및 검증 {#테스트}

2026년 11월 7일 현재 소스에 대해 다음 명령을 실행하였다. 저장 계층 26개, 변환기 11개 및 GUI 상태 5개를 합산하여 **42개 통과, 실패 0개**를 확인하였다.

```bash
cargo test --offline --workspace -- --test-threads=1
```

검증 항목에는 중복 입력의 순서 독립성, 마감 근거의 시각 비교, 검토 표시와 마감 판정의 분리, 임시 DB의 재시작·롤백 및 잠금 오류 후 재시도가 포함된다. 테스트에는 가상 자료와 임시 저장소를 사용하였다.

스크린샷은 기존 Xvfb 실행 과정에서 캡처한 프로토타입 화면이다. 해당 실행 기록에는 보관·읽음 조작, 빈 검색 결과 및 근거 화면 이동에 대한 확인 결과가 포함된다. 앞서 제시한 42개 통과 수치는 이 GUI 실행 기록과 구분한 자동 테스트 결과이다.

## 후속 개발 계획 {#계획}

1. 저장 모듈의 자료 목록 조회 결과와 GUI의 연계
2. 원본 식별자 기준의 선택·읽음·보관 상태 연결 및 저장 구조 정의
