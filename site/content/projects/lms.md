2026년 11월 · 개발 중 · 개인 프로젝트

## 프로젝트 개요

NAVI Study는 과목별 자료를 검색하고 과제의 마감 근거를 확인하기 위해 만드는 프로그램입니다. Rust workspace 안에 저장 계층, 카탈로그 변환기, Iced GUI를 나누어 구현했습니다.

**현재 GUI는 가상 자료로 동작하는 프로토타입입니다.** SQLite 저장 모듈은 별도로 구현되어 있지만 GUI의 실제 자료 조회·저장에는 아직 연결하지 않았습니다.

### 작업 범위 {#내가-맡은-작업}

개인 프로젝트로 자료 모델과 저장·변환 모듈, 화면의 검색·필터·상태 처리를 작업했습니다. 설계와 코드 작성·검증 과정에는 AI 도구의 도움을 받았습니다.

## 개발을 시작한 이유 {#해결하고-싶은-문제}

LMS에서 강의 자료·공지·과제를 따로 찾고, 본문에 적힌 마감일과 등록된 마감 정보를 다시 비교하는 과정이 번거로웠습니다. 자료를 과목별로 모으고 날짜가 어디서 나온 것인지 함께 확인하는 프로그램을 만들고자 했습니다.

## 사용 기술과 구성 {#구현-과정과-선택}

| 기술 | 현재 적용한 부분 |
| --- | --- |
| Rust | 자료 검증·변환·저장 모듈과 GUI 상태 처리 |

### Rust 선정 근거

Rust를 구현 언어로 선정하였다. 주요 선정 기준은 높은 런타임 성능, 컴파일 단계의 정적 검증, 메모리 안전성 및 향후 기능 확장 가능성이었다.

Rust는 가비지 컬렉터에 의존하지 않고 소유권과 빌림 체계로 메모리 접근과 자원 수명의 제약을 컴파일 단계에서 검증한다. 안전한 Rust 코드에서 데이터 경쟁과 다수의 메모리 안전성 관련 오류를 예방할 수 있다는 점을 고려하였다.

Cargo의 패키지 관리와 workspace 구성은 모듈화에 유리하다. 현재 프로젝트도 저장·변환·GUI를 세 crate로 분리하였다. 소유권과 타입 시스템에 대한 학습 비용은 있지만, 기술적 요구사항과 확장 가능성을 종합적으로 고려하여 채택하였다. NAVI Study의 런타임 성능 측정은 아직 수행하지 않았다.

### Iced와 SQLite 적용 현황

저장·변환·GUI를 같은 Rust workspace에 두고, Iced 화면이 변환기의 결과를 사용하도록 구성하였다. GUI는 tiny-skia 렌더러를 사용하며 Chromium이나 Electron을 포함하지 않는다. SQLite는 별도 서버 없이 로컬 파일로 다루는 구조이다.

자료를 저장할 때는 `records`에 종류·원본 식별자·제목·JSON payload를 넣고, `watermarks`에 과목과 자료 종류별 관측 시각을 기록합니다. 두 정보는 같은 트랜잭션에서 갱신합니다.

## 구현 중 해결한 문제 {#문제-해결}

### 같은 자료가 여러 번 들어오는 경우

과목 ID와 자료 종류, 원본 식별자가 같은 문서를 묶습니다. 가장 최근 `fetched_at`의 문서를 선택하고, 시각이 같으면 경로와 제목 순서로 결정합니다. 게시판 글은 게시판 ID와 글 ID를 함께 사용해 다른 글과 합쳐지지 않게 했습니다.

### 본문과 마감 정보가 다른 경우

완전한 날짜·시각은 같은 순간인지 비교합니다. `Z`와 시차 표기가 달라도 같은 순간이면 중복 후보로 처리합니다. 완전한 시각이 서로 다르면 `Conflict`로 남깁니다.

본문에 월·일만 있고 공식 시각과 맞지 않으면 연도나 시간을 임의로 보충하지 않고 `Unknown`과 확인 필요 근거를 남깁니다. 모든 자연어 날짜를 해석하는 기능은 아닙니다.

### 검토 표시가 마감을 확정하지 않도록 처리

마감을 검토했다는 UI 표시와 실제 마감 판정을 따로 두었습니다. `Acknowledge`는 화면의 검토 표시만 변경하며 `Unknown`이나 `Conflict`를 `Confirmed`로 바꾸지 않습니다. 이 관계를 확인하는 테스트가 있습니다.

## 테스트와 검증 {#테스트}

2026년 11월 7일 현재 코드에서 아래 명령을 다시 실행해 **42개 통과, 실패 0개**를 확인했습니다. 저장 계층 26개, 변환기 11개, GUI 상태 5개입니다.

```bash
cargo test --offline --workspace -- --test-threads=1
```

중복 자료의 순서를 바꿔도 결과가 같은지, 서로 다른 마감 근거가 충돌로 남는지, 검토 표시가 마감 판정을 바꾸지 않는지 등을 검사합니다. 저장 모듈은 임시 DB에서 재시작·롤백·중간 쓰기 실패 후 재시도도 검사합니다.

테스트는 가상 자료와 임시 저장소를 사용합니다. 스크린샷은 Xvfb에서 실행해 캡처한 기존 프로토타입 화면입니다. 해당 실행 기록에는 보관·읽음 조작, 빈 검색 결과, 근거 화면 이동을 확인한 결과가 있습니다. 위 42개는 이 화면 실행 기록과 구분한 자동 테스트 결과입니다.

## 다음 개발 계획 {#계획}

1. 저장 모듈의 자료 목록 조회 결과를 GUI에 연결합니다.
